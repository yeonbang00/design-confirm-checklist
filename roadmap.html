네이버 클로바 OCR 사용 중
이미지 속 텍스트 위치를 픽셀 좌표로 직접 측정해서, 3번(타이포·정렬·여백·명도대비)의 정렬 오차와 14번(매체 최적화)의 세이프존 침범량을 AI의 시각 판단이 아닌 실제 수치로 대조합니다.
네이버 클로바 OCR 서비스 안내 ↗
WCAG 명도 대비 체크 사용 중
브라우저가 OCR 텍스트 위치의 실제 픽셀을 직접 읽어 글자·배경 명도 대비를 계산하고, 3번(타이포·정렬·여백·명도대비) 판정에 근거로 반영합니다. 서버에 새 이미지 처리 라이브러리를 추가하지 않고 캔버스 API만으로 클라이언트에서 계산합니다.

판정 기준(WCAG AA): 대비 4.5:1 미만이면 기준 미달로 지적, 3:1 미만이면 명확히 낮은 값으로 보고 검토필요 이상으로 판정합니다. 3~4.5 사이는 근사치 특성상 애매한 구간이라 AI가 실제 화면을 한 번 더 시각적으로 확인한 뒤 판단합니다.
WCAG 2.1 명도 대비 기준 공식 문서 ↗
바른한글(나라인포테크) 맞춤법 검사 사용 중 (개인용)
지금 3번(타이포·정렬·여백·명도대비)에 OCR로 픽셀 위치를 대조하는 것처럼, 4번(정보 정확성) 오탈자 판정도 AI 시각 판단 대신 사전 기반 맞춤법 엔진으로 한 번 더 대조합니다.
현재 상태: 개인 비상업용 API 키로 연결되어 있습니다. 팀 차원의 상업적 이용은 나라인포테크에 별도 API 라이선스를 문의해서 가격·조건을 확인한 뒤 추후 업데이트할 예정입니다.

REVIEWING
검토 중 · 넣고 싶지만 아직 확신이 없는 기능
붙이면 도움이 될 만해서 조사까지 마쳤지만, 비용·정확도·자격 요건 때문에 아직 붙이지 않은 것들입니다.
매체 성과 데이터 연동 (Meta Marketing API · 네이버 성과형 디스플레이 광고 API · 카카오모먼트 API) AdCheck 최종 목표
지금까지 AdCheck는 배너가 게재되기 전 결함을 걸러내는 역할만 해왔습니다. 이 연동이 붙으면 배너가 게재된 이후 실제로 어떤 성과(클릭률·전환 등)를 냈는지를 매체사 API에서 직접 가져올 수 있게 됩니다.

여기서 중요한 건, AdCheck가 분석 시점에 이미 클로바 OCR로 요소별 데이터(텍스트 위치·크기, 정렬·여백 수치, 세이프존 침범량 등)를 픽셀 단위로 뽑아두고 있다는 점입니다. 이 구조화된 요소 데이터와 매체에서 가져온 실제 성과 데이터를 배너 단위로 이어 붙이면, "이 배너가 잘 됐다/안 됐다"는 결과만 보는 게 아니라 "CTA 버튼을 이 위치로 옮기니 클릭률이 올랐다"처럼 배너를 구성하는 요소 하나하나가 성과에 어떤 영향을 미쳤는지까지 분석할 수 있게 됩니다. 검수 전용 도구였던 AdCheck가 게재 전 검수와 게재 후 성과 분석을 하나의 데이터 흐름으로 잇는 지점이라, 지금 검토 중인 기능 가운데 최종 목표에 가장 직접적으로 맞닿아 있습니다.
왜 아직 안 했나: 세 매체 모두 API 신청에 자격 요건이 있습니다 — 네이버는 베타 파트너사 승인, 카카오는 공식대행사와의 사전 협의, 메타는 비즈니스 인증이 먼저 필요합니다. 국내 매체 비중이 큰 만큼 네이버·카카오 쪽을 먼저 신청해보는 게 우선순위상 맞을 것으로 보입니다.
네이버 성과형 디스플레이 광고 API 안내 ↗ 카카오모먼트 API 문서 ↗ Meta Marketing API 연동 예시 ↗
피그마 MCP 연동 (레이아웃 좌표 직접 수신) 정확도 개선 검토
지금 3번(타이포·정렬·여백·명도대비) 판정은 완성된 배너 이미지에서 클로바 OCR로 텍스트 위치를 픽셀 좌표로 "측정"하는 방식입니다. 피그마 MCP를 연결하면 디자이너가 작업한 원본 파일에서 레이어 트리와 실제 x/y 좌표, spacing 값을 그대로 받아올 수 있어서, 완성된 이미지에서 추론하는 대신 디자인 파일에 실제로 기록된 값을 곧바로 대조할 수 있게 됩니다.
왜 아직 안 했나: 3번 항목에서 반복적으로 나오는 오탐(스트록·그림자가 있는 텍스트를 정렬 오차로 오인하거나, 캔버스 중앙정렬을 좌우정렬 규칙으로 잘못 적용하는 경우 등)의 근본 원인이 결국 "이미지에서 좌표를 추론해야 한다"는 점에 있어서, 이 연동이 붙으면 구조적으로 해결될 가능성이 있습니다. 다만 모든 배너가 피그마로 작업되는 건 아니라서(포토샵·일러스트레이터로 작업하는 경우도 많음), 피그마 원본이 있을 때만 보강 데이터로 쓰는 방식으로 설계해야 합니다.

왜 아직 안 했나: 상업용 API가 월 $200(5,000건)부터 시작해서, 배너를 분석할 때마다 매번 돌리기보다는 필요할 때만 선택적으로 켜는 방식으로 붙이는 게 나을지 검토 중입니다.

블러·저품질 감지 신뢰도 검토 중
6·7번(합성 리얼리티, 피사체 보정)에서 잡아내는 AI 생성 특유의 아티팩트(울퉁불퉁한 질감 등)를 이미지 선명도 수치로 보강하려는 아이디어입니다.
왜 아직 안 했나: 배너는 단색 배경이나 그라디언트처럼 원래 "흐릿하게" 측정될 수 있는 영역이 많아서, 단순 선명도 수치만으로는 오탐(진짜 문제가 아닌데 문제로 잡히는 경우)이 많이 날 위험이 있습니다. 더 신뢰할 수 있는 방식을 찾는 중입니다.
GPT-5.6 Sol → Luna(무료 티어) 전환 검토 비용 절감 검토 중
OpenAI가 무료 사용자에게도 GPT-5.6 Luna를 기본 모델로 열었는데, 가격이 지금 쓰는 Sol 대비 1/25 수준입니다(1M 토큰당 입력 $5→$0.20, 출력 $30→$1.20). 다만 벤치마크를 보면 태스크 성격에 따라 격차가 크게 갈립니다 — 복합적인 다단계 추론 태스크에서는 Sol 91.5% vs Luna 41.3%로 격차가 크지만, 순수 이미지 이해 벤치마크에서는 Sol 73~74.6% vs Luna 66.2~74.1%로 격차가 훨씬 좁습니다.
왜 아직 안 했나: AdCheck는 이미지를 보고 17개 항목 전체에 대해 구조화된 판정과 reject 사유까지 생성하는 작업이라, 단순 비전 벤치마크보다는 격차가 큰 쪽인 복합 추론 벤치마크 성격에 더 가깝습니다. 특히 3번 항목처럼 미묘한 판정에서 지금도 오탐이 반복되는 걸 감안하면, 바로 전환하기보다는 동일한 배너 이미지를 Sol·Luna 양쪽에 같은 프롬프트로 돌려서 17개 항목 판정 결과를 직접 비교하는 검증이 먼저 필요합니다. 비용 차이가 25배인 만큼 검증해볼 가치는 있다고 보고 있습니다.

DECLINED
넣지 않기로 · 검토했지만 의도적으로 제외한 기능
기술적으로 가능하더라도 도구의 성격상 넣지 않기로 판단한 것들입니다.
매체별 배너 베리에이션 자동 생성 직접 구축 안 함
완성된 대표안(원본 배너)을 매체별 규격(사이즈·세이프존)에 맞춰 AI가 자동으로 리사이즈·재배치해서 여러 버전을 만들어주는 기능. OCR로 텍스트 위치를 읽고 매체 가이드로 목표 규격을 아는 것까지는 지금도 가능하지만, 실제로 카피·로고·색상을 정확히 유지하면서 레이아웃을 재구성하려면 PSD 레이어 편집·AI 배경 아웃페인팅 같은 완전히 다른 차원의 이미지 생성·편집 기능이 필요합니다.
왜 안 하기로 했나: 가장 중요한 이유는, 이미 성숙한 상용 서비스인 ResizeAd조차 스스로 명시한 한계가 뚜렷하다는 점입니다 — 카피 문구 자동 생성 안 됨, 원본 디자인 요소 형태 변경 안 됨, 잘린 피사체 AI 보정 안 됨. 이런 경우를 위해 디자이너가 직접 후보정하는 "프리미엄 서비스"(건당 ₩7,000)를 별도로 운영할 정도로, 전담 팀이 만든 제품도 완전 자동화가 안 되는 영역이라는 뜻입니다. 여기에 더해 (1) AdCheck는 지금까지 "검수" 도구로 범위를 지켜왔는데 이 기능은 그 경계를 넘어 "결과물 생성" 쪽으로 들어가고, (2) 이미 인크로스(INCROSS)의 ResizeAd가 PSD 업로드 → 매체·사이즈 선택 → AI 자동 생성 → 구매 방식으로 이 문제를 풀고 있는 상용 서비스라(건당 ₩2,500~1,500), 처음부터 다시 만들 이유가 없다고 판단했습니다.

대신 이렇게 연계 가능: ResizeAd로 만든 베리에이션 결과물을 AdCheck의 17개 체크리스트로 최종 검수하는 방식 — AI가 자동 생성한 소재라 사람 손을 덜 탄 부분(정렬·세이프존·오탈자·로고 규정 등)을 납품 전에 걸러내는 역할로 자연스럽게 연결됩니다.
