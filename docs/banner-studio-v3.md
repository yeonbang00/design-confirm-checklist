## 혜택과 카피

상품 설명은 최대 12,000자, 페이지 구간은 최대 40개를 유지한다. 원문에서 정확한 발췌가 확인된 혜택만 OFFER 토큰으로 제공한다. 카드/회원 등 조건은 별도 보관해 최종 문구에 함께 전달한다. 계산한 할인율을 표시 할인율로 확정하지 않으며, 2개 구성을 1+1 행사로 바꾸지 않는다.

명시된 가격·수량·혜택 또는 선택한 상세 근거의 숫자만 사용한다. 잘못된 문구는 1회 교정 후 다시 검사한다. 제작 설명이 광고 카피로 들어가는 경우와 같은 가격 중복도 차단한다. 원산지·개봉기한보다 성분·소재·보습·마무리 등 구매 이유를 먼저 기획한다.

결과 화면의 숨긴 편집 패널이 차지하던 빈 열과 모바일 푸터의 가로 넘침도 정리했다.


## 지속 연계와 카드 혜택 제외

- 카드 즉시할인·청구할인·무이자/할부는 기본 광고 후보에서 제외한다. 수집 원문은 유지하되, 기획 후보·카피 토큰·최종 카피 검증에 같은 정책을 적용한다. 일반 할인·쿠폰·증정·배송 정보는 근거가 확인된 경우 계속 활용한다.
- `criteria-guide.html`이 공통 공개 가이드 원본이다. 분석, 카피 생성, 완성 이미지 생성이 서버에서 동일 파일을 읽는다. 17개 항목의 확인 사항/반려 예시는 유지하고, 단계별 관련 항목의 설명까지 전달한다. 상세 판정의 기존 예외와 브랜드·매체 지침은 유지한다. 가이드 구조가 깨지면 조용히 생략하지 않고 오류를 반환한다.
- 공개 가이드를 수정·배포하면 다음 분석/생성에 적용된다. 생성 전에는 최신 업로드 이미지와 축 태그를 다시 읽는다. 조회 실패 시 오래된 목록만으로 계속하지 않는다. 레퍼런스 추가/재태깅은 배포 없이 다음 생성에 반영된다.
- 카피·이미지의 가이드 버전, 혜택 정책 버전, 레퍼런스 목록·축의 지문과 개수, 선택한 참고 이미지를 제작 기록에 남긴다. 저장된 결과가 과거 버전인지 추적할 수 있다.
- 이것은 최신 자료를 검색하고 공통 규칙을 적용하는 연계다. 분석할 때마다 모델을 자동 재학습하거나 임의 판정을 전체 규칙으로 승격하는 기능은 아니다. 분석에서 확인한 반복 문제를 항목 가이드에 반영하면 생성도 그 기준을 공유한다.
- 추가 검증: 카드 5% 할인과 무료배송을 함께 넣은 실제 카피 API 요청에서 카드 혜택 없이 기본 판매가·무료배송·CTA가 반환됐다. 공개 가이드 지문과 정책 버전도 함께 반환됐다. 최신 뷰티 레퍼런스 231개 조회에서 목록/태그 지문과 `no-store` 응답을 확인했다. 가이드 변경·태그 변경·업로드 추가에 따른 버전 변경 및 목록 조회 실패 차단을 자동 검사했다.
- 최종 리얼베리어 재검증에서 5종은 완료되고 1종은 가격 중복 검사로 차단됐다. 이 결과를 성공으로 표시하지 않는다. OCR 영역 사이 숫자가 붙어 할인율로 오인되는 별도 문제는 수정하고 회귀 검사했다.


## v3.1 — 반복 원본·무드·타이포 연결 수정

사용자가 제공한 블루핏 12개 생성 결과와 패션/화장품 레퍼런스를 비교한 결과, 장식의 종류보다 실제 사진 선택과 광고 정보의 위계가 문제였다. 같은 정면 모델 반복, 큰 무료배송/쿠폰, 잘못된 브랜드 로고, 원본을 생성 결과에 사각형으로 덮는 처리, 실제 레퍼런스를 생성 모델에 전달하지 않는 경로를 함께 수정했다.

현재 경로는 **실제 사진과 원문 → 전체 범위에서 사진 분석 → 무드·포즈·색상·조명·제형 기록 → 활용 영역 추출 → 자료에 맞는 6종과 기본안 → 맞는 레퍼런스 선택 → 실제 배치 관찰 → 카피와 완성 이미지 → 기존 OCR/상품 검사 → 다운로드**다.

- 분석 예산 24장 안에서 앞부분만 자르지 않고 마지막 상세까지 고르게 선택한다. 추출 예산 24개는 각 이미지에 첫 영역을 먼저 배정한 뒤 두 번째·세 번째를 배정한다. 사진 크기도 개수 변경 여부와 무관하게 저장한다.
- 선택한 원본의 사용 횟수·포즈·컬러를 고려해 시안별 사진을 분배한다. 풍부한 패션 자료에는 다른 실제 착장과 컬러 구성이 포함된다. 같은 URL/영역의 중복을 제외한다. 서로 다른 URL의 동일 사진을 시각적으로 중복 검출하는 기능은 아니다.
- 상품명·판매가 기본안은 하나를 보장한다. 나머지도 실제 상품 종류를 메인/서브에서 식별할 수 있어야 한다. 무료배송은 보조 정보이며 쿠폰안의 생성 조건이 아니다. 확인된 일반 할인·쿠폰·증정은 계속 활용하고 카드 할인은 기본 제외한다.
- 실제 상세 문구와 사진의 근거를 카피에 전달한다. 레퍼런스는 사실 근거로 쓰지 않는다. 제품 형태·컬러·제형의 출처를 상품 사진으로 제한한다. 원단 접사는 의자나 행거에 놓을 완제품으로 취급하지 않는다. 생원물 상품은 조리 사진으로 대체하지 않는다.
- 브랜드 무드를 사진에서 관찰하고 기획·레퍼런스 선택·카피·이미지에 함께 전달한다. 차분한 무드에 집게 장난감/극적인 무대를 배정하지 않는다. 사람을 장난감이나 캡슐 속 상품으로 연출하지 않는다. 사진·템플릿·그래픽을 섞되 모든 안에 같은 장식을 강제하지 않는다.
- 선택 레퍼런스의 실제 이미지와 제목/서브 줄 수·상대 글자 크기·텍스트 영역·사진 비중·CTA 형태를 생성 모델에 전달한다. 같은 제목 두 줄의 무의미한 크기 차이, 과도한 자간/세로 변형, 작은 서브, 큰 배송 딱지와 반복 원을 제한한다. 고딕은 기본 선호이며 굵은 고딕만 강제하지 않고 명조 비율도 고정하지 않는다. 로고는 디자이너가 나중에 넣는다.
- 고정 사진창을 준비하고 생성 후 원본을 덮던 경로를 제거했다. 실제 사진을 원본으로 전달하되 이미지 모델이 사진과 타이포를 함께 구성한다. 결과의 픽셀 단위 원본 보존을 보장하지 않는다.
- 변경되지 않은 레퍼런스 관찰은 브라우저에 재사용한다. 이미지 URL·축 태그·수정일·설명 또는 계약 버전이 달라지면 다시 관찰한다. 최신 라이브러리 검색 및 항목 가이드 연계는 유지한다. 실제 디자인 레퍼런스를 이미지 생성 입력에 추가하므로 이미지 입력 비용이 늘 수 있고, 관찰 재사용이 API 이용 전체를 무료로 만드는 것은 아니다.
- 기존 OCR 응답으로 광고 글자의 과도한 크기/작은 서브와 CTA/두 줄 위계 불균형을 보수적으로 검사한다. 패키지 라벨은 별도 취급한다. 이는 사진 미감이나 브랜드 무드가 성공했다는 자동 판정이 아니다.

### 이번 검증

유료 API를 호출하지 않았다. 테스트 6개 파일 통과. 추가 회귀 검사는 풍부한 패션 200회, 뷰티 50회, 원물/밀키트·기타 업종, 뒤쪽 상세 선택·추출 예산 배분, 상품 기본 카피, 과도한 타이포, 무드에 맞는 레퍼런스, 관찰 캐시 무효화, 실제 productPhotos/bannerImage/studioCopy 핸들러를 포함한다. 네트워크를 가로채 상품 사진과 디자인 레퍼런스가 multipart에서 구분되는 것까지 확인했다. 실제 새 이미지의 미감은 이번 검증에 포함하지 않는다.


## 상품 브랜드와 판매처 로고 분리

사용자 확인에서 개선된 구도는 유지하되, 첫 기본안 외에 상품 브랜드가 사라진 문제가 있었다. 신세계쇼핑처럼 여러 브랜드를 파는 판매처의 로고는 상품 브랜드를 대신하지 않는다. 로고 생성 금지를 상품 브랜드명까지 제외하는 규칙으로 적용한 것이 원인이었다.

`product.brand`가 확인되면 각 완성 배너의 메인 또는 서브에 브랜드가 있는지 확인한다. 이미 있으면 별도 표기를 추가하지 않고, 없으면 `brandLine`으로 전달해 제목/서브/상품 정보 근처에 읽히는 일반 텍스트로 한 번 표기한다. 큰 헤드라인이나 로고 형태를 강제하지 않는다. 판매처 로고는 디자이너가 추가하며 상품 라벨은 보존한다. 브랜드가 없으면 판매처 도메인이나 레퍼런스로 추정하지 않는다.

완성 후 기존 OCR에서 브랜드 누락도 확인한다. 별도 유료 호출은 추가하지 않는다. 사용자 스크린샷의 여섯 카피, 영문·숫자 포함 브랜드, 기존 제목/서브와 중복 방지, 미확인 브랜드, 실제 생성 요청의 brandLine 전달을 검사했고 테스트 7개 파일을 통과했다. 이번 수정으로 기존 생성 PNG가 자동 변경되지는 않는다.


## 결과 화면 간소화 — 2026-09-16

사용자 요청으로 전체 다운로드·처음부터 고화질·상품 정보 수정·저장함 진입 버튼과 결과 상단 설명을 제거했다. 완료된 카드의 문구/숫자 검사 완료 상태도 숨기되 진행·실패 상태는 유지한다. 카드 버튼은 ‘이미지 다운로드’와 ‘텍스트 없는 이미지 다운로드’로 통일한다. 후자는 첫 요청에서 글자 제거 후 다운로드하고, 같은 결과는 재생성 없이 재사용한다. 기존 저장 데이터와 생성/검수 로직은 삭제하지 않았다. 로컬 실제 화면에서 여섯 카드, 초기화/진행 상태 전환, 데스크톱·390px 모바일을 확인했다. 유료 생성은 실행하지 않았다.

## 식품 실제 사진 우선 계약 — 2026-09-16

조선호텔 LA갈비 사례: 쓸 수 있는 실제 사진은 완성 음식 접사, 접시에 담긴 상차림,
판매 트레이 약 3종이었으나 기존 공통 기획기는 서로 다른 원본을 배정하려고 조리법
패널과 원물 사진까지 사용했다. 조리 사진 자격은 밀키트로 좁혀져 있었고 생성 결과
동일성 검사는 뷰티에만 연결되어 있었다. 글자 대조 실패를 이미지 생성 실패로
표시한 카드도 있었으므로, 스크린샷의 실패 3건을 이미지 API 장애로 해석하지 않는다.

비교 패키지의 장점은 원본 갈비의 윤기·뼈·고명과 실제 베이지 트레이를 유지하면서
접사/상차림/패키지 병치로 화면을 달리한 것이다. 그 패키지의 리뷰와 WELCOME,
더블멤버십 금액은 본 상품의 확인 근거가 아니므로 가져오지 않는다. 모든 사진을
정확히 보존했다고 주장하지 않으며 생성 결과는 별도 비교가 필요하다.

- `studio-food-policy.mjs`: 완성 음식/원물/포장과 조리 과정/정보 패널을 구분한다.
  해당 상품의 실제 조리 예시는 밀키트가 아니어도 사용한다. 문구만으로 생고기를
  익히거나 양념 붓기·굽기·절단을 생성하지 않는다. 상태가 불명확하면 후보 제외.
- `studio-food-plan.mjs`: 완성 음식 사진이 있으면 6종 모두의 중심 자료로 우선한다.
  기본 상품명·가격, 상차림, 실제 접사, 실제 포장 병치, 여백/그래픽/검증 혜택 등을
  자료와 무드에 맞춰 구성한다. 원본 1장을 여러 구도에 재사용해도 된다. 포장이
  없으면 새 포장을 추가하지 않고, 포장만 있으면 내용물을 상상해 꺼내지 않는다.
- 사진 영역 정규화는 서버와 브라우저가 같은 함수를 사용하여 `foodUse`,
  `foodState`, `actualPreparedMeal`, `packageVisible`이 사라지지 않도록 한다.
- 실제 포장을 포함한 사진은 휴리스틱 로고 덮기에서 제외한다. 생성 요청과 비교
  검수에 동일한 선택 원본/추출 이미지 바이트를 전달한다. 레퍼런스는 디자인만 참고.
- 식품도 생성 후 음식 형태·상태·포장 동일성 비교를 1회 수행한다. 불일치/불확실은
  완료로 처리하지 않는다. 추가 이미지 자동 재생성은 하지 않는다. 이 비교는 운영 시
  추가 비전 호출이며, 기존 OCR 숫자 검사는 그대로 유지한다.

검증은 유료 이미지 생성 없이 실제 API 핸들러의 네트워크 응답을 대체해 수행한다.
3개 자료/1개 자료/포장만/원물만/정보·조리과정만인 상품, 카드혜택 제외, 200회 구성,
분류→영역 추출 계약→기획→생성 요청→동일성 검수 경로를 회귀 테스트로 확인한다.
실제 생성 품질과 비전 검사의 판정 정확도는 이번 코드 테스트로 보증하지 않는다.


## v3.3 — 전략 조합과 신세계쇼핑 모델 확장 (2026-09-16)

앞 절의 식품 고정 기본안·상차림·접사·포장 배정은 이 절의 조합 선택으로 대체한다.
실제 음식과 포장의 동일성을 지키는 원칙은 유지한다.

### 식품: 전략 × 표현 × 자료 × 무드

전략은 상품명·가격, 상품 매력, 식사 제안, 포장·구성, 가격·구성, 확인된 상품 특징,
일반 구매 혜택, 실제 구매 후기, 품질 근거, 비교 근거, 선물 제안 중 자료가 충족하는
것만 후보가 된다. 후기는 출처가 있는 원문, 비교/인증은 해당 종류의 근거가 필요하다.
카드 결제 혜택은 기존 정책대로 제외한다.

표현은 음식 전면, 상차림, 음식 접사, 실제 포장과 음식, 여백 화보, 정보 카드,
그래픽 포스터, 질감 배경, 두 구도, 타이포 강조를 자료와 무드에 맞춰 조합한다.
특정 전략이나 표현을 특정 번호에 고정하지 않는다. 회차별 전략 선호를 샘플링하고,
한 세트 내 중복과 최근 완료 조합을 감점한다. 기본안은 최대 한 안이며 필수 슬롯은 아니다.
자료가 빈약하면 새로운 주장/포장을 만들기보다 같은 실제 상품을 다른 배치로 재사용한다.

매 생성 시 최신 레퍼런스를 먼저 불러와 축 적합도를 선택에 반영한다. 이어서 각 안의
축·무드에 맞는 실제 레퍼런스를 연결한다. 완료된 전략/표현/원본 조합과 사용한 레퍼런스는
브라우저 이력으로 남긴다. 이는 학습 모델의 업데이트나 광고 실적에 의한 최적화는 아니다.

상차림에는 소량의 밥·김치, 햄버거 옆 토마토 같은 맥락에 맞는 곁들임 연출을 허용한다.
본제품보다 크기·밝기·채도·선명도로 시선을 끌지 않게 하고 본제품과 분리한다.
곁들임을 본제품 안에 넣거나 포함 상품/확인된 원재료로 소개하지 않는다. 본제품의
상태·조각·뼈·소스·기존 고명·포장은 유지한다. 생성과 검수에 동일한 허용 정책을 전달한다.

### 신세계쇼핑 패션: 원본 우선 + 한 안의 모델 확장

사용자 지정 타깃은 30~40대 여성이다. 신세계쇼핑의 상·하의/아우터에 적용하며
실제 원본 모델과 다양한 포즈/컬러를 먼저 활용한다. 옷의 전체 형태를 확인한 사진이
있으면 여섯 안 중 한 안을 깔끔하고 세련된 30~40대 한국인 여성 패션 모델로 확장한다.
남성복·아동복, 다른 판매처, 접사/가림으로 옷의 형태를 확인할 수 없는 자료는 제외한다.

원본 얼굴을 나이 들게 바꾸지 않고 새로운 가상 모델을 연출한다. 과도하게 나이 들어
보이는 스타일이나 일반인 스냅사진 분위기를 요구하지 않는다. 상품의 차분함·감성·
고급스러움 등 관찰된 무드와 일관된 빛을 따른다. 옷의 실루엣·기장·목선·소매·단추·
패턴 간격·색·재질을 유지한다. 광고 문구에 타깃 나이/국적을 쓰거나 실제 구매자·
후기 작성자처럼 소개하지 않는다. 얼굴에서 실제 인종이나 정확한 나이를 판정하지 않는다.

분류→영역 추출→기획에 `garmentComplete`를 전달한다. R31 생성 후 의류 동일성 비교를
한 번 수행하며, 새 얼굴은 허용하되 옷 변경/불확실/부자연스러운 합성은 실패 처리한다.
이는 운영 시 해당 한 안에 추가되는 비전 호출이며 이미지 자동 재생성은 하지 않는다.

### 검증 범위

유료 이미지 생성 없이 테스트 9개 파일을 실행했다. 동일 식품 자료로 1,000회 기획해
순서를 제외한 전략·표현 조합 997가지, 전략 묶음 20가지를 확인했다. 신세계쇼핑 패션
200회에서 원본 포즈/컬러 안과 한 개의 모델 확장 안을 함께 배정했고, 타 판매처·남성/아동·
의류 자료 부족 시에는 확장하지 않았다. 실제 API 핸들러를 네트워크 모의 응답으로 검사해
후기 원문 연결, 선택 원본 전달, 음식 곁들임 정책, 의류 검수 실패 처리를 확인했다.
이 수치는 예시 자료의 기획 다양성 검사이며 실제 이미지 미감/검수 정확도나 광고 성과를 보증하지 않는다.
